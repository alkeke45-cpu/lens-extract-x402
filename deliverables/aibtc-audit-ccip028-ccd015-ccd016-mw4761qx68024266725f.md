# Audit — CCIP-028 + ccd015 MIA burn book + ccd016 sBTC→STX vault (pre-deploy)

Scope: `ccip028.clar` (50 L), `ccd015-redemption-book-mia-stx` (510 L), `ccd016-swap-vault-mia-v2` (1141 L), branch `review/ccip028-direct-activation`. Prior paid findings in `README-vault.md` were read first and excluded (see §3).

## 1. Method & reproducible checks

- Full read of ccip028 and ccd015; ccd016 read in full for constants/vars (L100–258), setters and funding/exit paths (L259–520), remainder by grep of every `define-public`, `asserts!`, and `is-dao-or-extension` call site.

- Guard analysis: every writer of ccd015 `par-scaled` (only `update-par`, L150) and of ccd016 dials (DAO-gated setters only). Algebraic verification of ccd015 `settle-step`'s partial-fill price invariant and of par overflow bounds.

## 3. Checked-and-clean (per scope bullet)

**ccip028 authorization.** `execute` (L11) asserts `contract-caller = DAO ∧ tx-sender = DAO` (L15) before any state change. A direct call from the deployer or an approver has `contract-caller ≠ DAO` and aborts u28000. The only path that satisfies both is base-dao's own `as-contract` execute, i.e. the existing ccd001 approver flow; ccip028 adds no other public function. The `sender` parameter is used only in the `print` event (L45–46) — no authorization, amount, or destination depends on it, so a spoofed `sender` cannot influence execution.

**Re-init / re-run guard.** L16–17 requires `ccd015.get-par-scaled = u0`. `par-scaled` starts u0 (ccd015 L102) and its sole writer, `update-par`, is DAO/extension-gated and asserts `snapshot > u0` before writing (L150–158); no code path can return it to u0. Once activation succeeds the guard is permanently closed — including against a second DAO execution, which base-dao independently refuses. Conversely the guard cannot be pre-tripped by an attacker: `update-par`, `set-paused`, and `set-min-deposit` all require `is-dao-or-extension` (ccd015 L130/138/150), and before activation the proposal contract is not a base-dao extension (ccip028 grants extension only to the vault, L23–24), so only the `tx-sender = base-dao` arm — the activation call itself — can set par first.

**Ordering / atomicity / half-apply.** `execute` is a single public function; every step is sequenced with `try!` (L23–44), so any failure (e.g. `update-par` returning u15012 if treasury or supply is zero) aborts the transaction and rolls back the extension grant, allowlist change, and all dial writes. No secondary entry points or deferred steps exist. Order is also safe: extension and allowlist first, vault dials next, book `set-min-deposit` → `update-par` → `set-paused false` last (L42–44), so the book is never live with an unset par.

**Wrong principals.** All ccip028 targets are either the hard-coded live DAO/treasury/sBTC principals (L23–26, matching ccd015 L78/83/85 and ccd016 L141/144) or relative `.ccd015-…` / `.ccd016-…` references binding to ccip028's own deployer. With the mandated same-deployer, book→vault→proposal deploy order, these coincide with the vault's own book binding (`STX_FAIR_BOOK`, ccd016 L150, also relative). A copy deployed from another address would point at nonexistent contracts and fail atomically; executing it would require ccd001 approvers to approve that copy — the excluded malicious-approver case. The book correctly receives **no** extension: its DAO-gated functions pass via the `tx-sender = base-dao` arm during proposal execution, and it needs no treasury withdrawal right (it burns MIA it owns).

**Params vs caps (ccd016 setters all enforce `≤ MAX`, L259–347).** window u288 ≤ 1008; leeway u1000 ≤ 1000 (at cap, §2); slippage u100 ≤ 1000; max-chunk u1000000 ≤ 100000000 and > u0; maker-spread u1 ≤ 50 (and correctly non-zero — ccd016 L202–206 documents that a 0 spread prevents the peg from resting); dia-band u1000 ≤ 5000; router-cooldown u1 ≤ 144; no-pyth-slippage u1000 ≤ 5000; pyth-fee-budget u0 ≤ 10000000. Eight of nine values equal the contracts' own defaults; only leeway differs. Book: `set-min-deposit u100000000000` = 100,000 × 10⁶ micro-MIA (L42), identical to ccd015's default (L99); MIA's 6 decimals are used consistently.

**Par formula, units, treasury read (ccd015).** `calculate-par` (L333) = `treasury-ustx × PAR_SCALE (10⁸) / supply`, `none` if either input is zero, and `update-par` refuses a zero snapshot — activation cannot commit a zero or attacker-chosen par; the executor supplies no number. `get-mia-total-supply` (L370) = v1 supply × 10⁶ (v1 has 0 decimals) + v2 total supply (6 decimals), the ratified combined denominator. `get-treasury-balance` (L351) reads `stx-account` (locked + unlocked) of mining-v3 **and** of ccd014 pox5 staking — exactly the scoped read; `stx-account` is required because stacked STX is locked and invisible to `stx-get-balance`. Caveat noted, not a finding: the sum is correct as long as the two accounts' locked balances are disjoint — the post-CCIP-027 migration state described in ccd015 L81–85; ccd014 is outside this file set. `at-or-below-par?` (L302) cross-multiplies (`ask × 10⁸ ≤ amount × par-scaled`), no truncating division; worst-case products (~10²³) are far below 2¹²⁸. `settle-step` partial fill (L462ff): `taken = amount × remaining / ask` floors, and `taken × ask ≤ amount × remaining` is exactly the condition that the leftover record's implied price stays ≤ its original price ≤ par — verified algebraically; sort order and the par ceiling both survive a partial fill.

**Set interaction.** Vault STX reaches only the book (`fuel-fair-book` → `STX_FAIR_BOOK`, ccd016 L458ff); book crossing spends only the book's own STX and re-checks every offer against the committed par at fill time (ccd015 L256ff), so a later par refresh cannot make the book overpay. Pre-activation the book is inert despite `paused` defaulting to false (ccd015 L98): `place-offer` and `cross-book` abort while `par-scaled = u0`, and `change-offer` cannot pass `at-or-below-par?` at par 0. Vault funding depends on exactly the two grants ccip028 makes — extension status for `withdraw-ft` and sBTC on the treasury allowlist (ccd016 L379–381, `fund-from-treasury` L381) — both made atomically before any funding can occur. No ccip028-set param is read with different units by the other contract: vault dials are bps/sats/burn-blocks as the setters define them; the book's only ccip028-set values are min-deposit (micro-MIA) and the formula-derived par.
